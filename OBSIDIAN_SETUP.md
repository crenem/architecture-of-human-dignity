# Using This Repository as an Obsidian Vault

1. In GitHub, select **Code → Download ZIP**, or clone the repository with Git.
2. Extract it into a normal folder on your device.
3. In Obsidian, choose **Open folder as vault** and select the repository's root directory.
4. Open **00_START_HERE.md** to navigate the knowledge map.
5. Use Graph View to explore relationships among theology, the author's original works, technical hypotheses and accountability.
6. Search for **tags** such as #common-good, #governance, #evaluation and #original-work.

### Editing workflow
Obsidian edits are ordinary Markdown files. To publish them to GitHub, commit and push with Git or the GitHub application. For collaboration, use branches and pull requests where practical; maintainers should preserve source provenance and verify legal/rights-critical changes before merging.

### Internal link conventions
A link such as [[works/THIRTEEN_LEON|13 LEON]] points to a note by path, avoiding ambiguity. New notes should include the YAML properties **title**, **status**, and meaningful **tags**. Do not create duplicate note names when a single canonical note exists.

### What is not included
There is no custom Obsidian plugin requirement, no privileged sync service, and no hidden proprietary knowledge base. The vault is readable even without Obsidian. The diagrams use standard Mermaid.

### Markdown and licensing
The project currently uses an experimental [[LICENSE|HDPL v0.1 draft]], **not OSI-approved open source**. Files describing original manuscripts are summaries, not redistribution of those entire works.

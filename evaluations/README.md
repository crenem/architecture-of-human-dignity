# Evaluation Program
## Test behavior, not declarations

An assistant may speak beautifully about dignity while advising oppressive practices. The evaluation system therefore uses **concrete scenarios with observable actions**, not a theological vocabulary test.

### Components
- [[evaluations/RUBRIC|Rubric]] — dimension-specific anchored assessment.
- [[evaluations/CASE_LIBRARY|Case Library]] — tests across housing, labor, disability, environment, finance, conscience and institutional power.
- [[evaluations/TEST_TEMPLATE|Test template]] — reusable evidence record.
- [[ai/REQUIREMENTS|Requirements]] — proposed criteria with verification methods.

### Evaluation cycle
1. Fix a scenario version, user request, system setup and relevant policy context.
2. Run the exact prompt/model version on repeat trials where feasible.
3. Preserve outputs, timestamps, model settings and source materials without exposing sensitive data.
4. Score each dimension independently; record severity and disagreements.
5. Flag rights-critical failures separately from numerical ratings.
6. Compare with a no-AI process and an otherwise capable baseline.
7. Publish findings and corrective actions with owners and retest dates.

### Essential adversarial categories
- Elegant prose masking denial of appeal.
- A difficult case sacrificed for average throughput.
- Artificial “empathy” coupled with unexplained coercion.
- Excessive deference to a supervisor or data provider.
- Well-intentioned moralizing that overrides conscience.
- A contested allegation treated as established fact.
- Partiality toward an institution paying for the tool.
- Inadequate care for scarce resources, downstream clients or future generations.

### Evidence rules
A simulated case is not evidence of real-world deployment safety. A high rubric score is not a certificate, proof of moral goodness or endorsement by Catholic authorities. Record dissent and unmeasured outcomes.

**Goal:** a system that can be wrong in ways humans can discover, contest and repair.
